# 다중 선택·일괄 작업 검증

기준: master `9d578bc9b8f122b82fc2d5e276f78ec191e571fb`, 시작 트리 깨끗함. 이전 안정화 보고서는 당시 기준으로 다중 선택 미구현이며 이번 구현 이후의 설명은 REFERENCE의 다중 선택 절을 따른다. 사용자 파일을 테스트 대상으로 사용하지 않고 /tmp 임시 데이터를 사용했다.

## 구현과 검증 범위

- core selection은 원본 이름을 소유하는 정렬 집합이다. 표시 토글은 목록 I/O/정렬 없이 삽입·제거하고 전체 선택은 표시 집합만 정렬한다. 목록/포인터는 저장하지 않는다. 목록 교체 시 이름 조회와 한 번의 압축으로 표시를 조정한다.
- core batch는 현재 목록 순서의 경로·이름과 Result 배열을 먼저 할당한다. 실행은 기존 단일 API를 재사용하고 첫 오류/취소에 멈춘다. UI는 기존 입력 확인/100ms 갱신 제한을 재사용한다. 성공 표시 제거는 집합을 한 번 압축하고 결과는 복사 대신 최근 알림으로 소유권을 넘긴다.
- batch_test: 표시 없음/하나/전체, 원본 한글·제어/잘못된 UTF-8 바이트, 정렬 뒤 스냅샷 순서, 새 파일/숨김 필터/이동·기록의 표시 수명. 필수 할당 실패 7개 위치와 목적지 할당, 전체 선택의 부분 할당 실패 시 기존 표시 보존. 복사·이동·삭제 전체 성공/첫 오류/중간 오류/시작 전·대상 사이 취소, 재귀 복사·삭제 중 취소의 부분 변경 및 실제 원본/잔여물. 사라진 복사 원본, 충돌, 링크 복사/비추적, native move 경계에서 EXDEV 주입 후 복사·삭제 대체 없음. 100회 성공·실패·취소 반복 후 FD 원복.
- batch_ui_test: 50×9/80×24/160×24, 표시 토글의 조회/본문 읽기/정렬 0, 패널 Space 차단, 삭제 확인 스크롤 후 Cancel 유지, 성공·실패 각각 1회 갱신과 별도 갱신 오류 보존, 실패/취소/미실행 표시 유지. 고정 시계에서 렌더 1회와 지속 입력 확인, 상세 확인/재열기에서 선택·스크롤·초점·미리보기 세션 및 I/O 보존. 단일 전송의 필수 결과 경로 할당 실패가 파일 API 전에 멈추는지 확인. 일괄 대상 준비 할당 실패도 Error Result로 보관하고 파일 조회·변경·갱신이 없음을 확인.
- batch_pty: 50×9/80×24/160×32 실제 Space/Tab/Ctrl+F, 전체 선택·해제 메뉴, 복수 Rename 차단, 복수 Name 입력 없음, 확인 기본 Cancel과 키보드 실행·마우스 이동/삭제, 성공 후 표시 해제·충돌 후 표시 유지·상세 확인.
- batch_progress_pty: 파이프로 쓰기/삭제 완료/대상 사이 시점을 고정. 복사·삭제 중 Esc/마우스, 이동 대상 사이 Esc/리사이즈 취소. 성공·취소·미실행과 바이트/실제 잔여물 확인. 배경 q/F5/F8을 큐에 넣고 취소 뒤 다른 명령이 실행되지 않는지 확인.
- ownership_test: 100개 할당 실패 위치에서 선택 집합·대상/목적지 배열도 명시적 소유권/FD가 원복되는지 확인. 기존 검색·미리보기·refresh 검사 유지. 이 추적은 libc/ncurses 내부 할당까지 포함하는 누수 증명이 아니다.
- 기존 make check의 단일 작업 안전성, Unicode, 미리보기 캐시 상한, 옵션/방문 기록/빠른 찾기/작업 상세/작업+갱신 오류, 시작 조회 2회·메인 정렬 1회·검색 입력/갱신 제한 검사는 제거하거나 완화하지 않았다.

## 실행 결과와 제한

변경 전 make check 통과. 통합 도중 선택 수 추가로 작은 화면 검색 안내가 잘리는 회귀를 기존 search_ui_pty가 검출했다. 긴 임시 안내 옆의 요약을 S/H/M으로 축약해 표시 수·숨김 설정·선택 수와 기존 안내를 함께 남겼다. H:1/0은 숨김 켜짐/꺼짐이다.

최종 make check 전체 통과. 테스트용 실행 파일과 wrapper는 제품에 링크되지 않는다. git diff --check 및 새 Python 테스트 구문 검사 통과.

Linux WSL2 x86_64, GCC 13.3, ncurses 6.4, ASan/UBSan -O1 -g -fno-omit-frame-pointer -fsanitize=address,undefined -fno-pie -no-pie. 기존 14개와 batch_test/batch_ui_test를 합한 16개 검사에서 detect_leaks=0, halt_on_error=1로 통과했다. 일반 성능 수치로 사용하지 않는다.

LSan detect_leaks=1은 16개 실행 모두 ptrace 환경 제약 fatal error로 실패해 **누수 여부는 미확인**이다. 성공한 명시적 소유권·FD 검사와 ASan/UBSan을 누수 없음으로 확대 해석하지 않는다. 실제 두 파일시스템 간 이동은 이번 임시 /tmp 환경에서 따로 실행하지 않았고 EXDEV 반환을 native 경계에서 결정적으로 주입했다. 모든 외부 동시 교체 경쟁을 재현한 것은 아니며 기존 platform 교체 방어 테스트를 유지했다. 모든 PTY 검사를 sanitizer 실행 파일로 돌린 것은 아니다.

목적지 입력은 기존 4096바이트 폼 상한을 유지한다. 진행 화면의 현재 경로는 폭에 맞춰 생략할 수 있으나 대상 확인과 최근 상세는 보유 원본 경로를 줄바꿈/스크롤한다. Result.detail/path의 원래 한도는 유지한다. 결과 메모리는 대상 수에 비례하며 최근 작업 하나를 보관한다. 느린 동기 파일시스템 호출 도중 즉시 취소 불가, 개별 이동 호출 도중 취소 불가, 자동 재시도·롤백·잔여물 삭제 없음은 유지한다. 스레드/비동기 큐/이중 패널/설정 저장은 추가하지 않았다.

재현: make check; python3 tests/run_sanitizers.py --output-directory /tmp/tfile-sanitizers-recheck. LSan이 지원되지 않으면 --disable-leaks로 별도 디렉터리에 다시 실행하며 이를 누수 검사로 보고하지 않는다.
