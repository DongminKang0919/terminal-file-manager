## 이번 개선

검색은 모든 유효 항목의 경로를 추가 복제하던 처리를 제거했다. 결과에 보관한 항목은 해당 경로를 빌리고, 비일치 항목은 콜백·하위 탐색이 끝난 뒤 해제한다. 결과 배열이 재할당되어도 경로 문자열의 주소는 유지된다. 검색 순서·제한·오류·취소 정책은 유지한다.

텍스트 미리보기의 먼 위치 이동에서는 읽은 모든 행을 문자열로 할당하지 않고 마지막 512개 캐시 범위만 할당한다. 파일은 계속 순차 읽기하므로 읽기량 감소나 상수 시간 이동을 주장하지 않는다. 보관하지 않은 구간은 캐시 시작점에서 제외해 파일 끝을 넘는 이동 후 뒤로 이동할 때 다시 읽도록 한다.

`tests/performance_test.c`는 아래 처리량과 결과 내용, 재귀 중 결과 배열 성장, 근거리 뒤로 이동 시 캐시 사용, 파일 끝 이후 이동·복귀와 처음으로 돌아가기까지 검사한다. `check-core`와 native sanitizer runner에 포함했다. 시간 제한 대신 문자열 복제 횟수 상한을 검사해 머신 속도 차이에 영향을 받지 않는다.

| 동일 fixture | 수정 전 문자열 복제 | 수정 후 문자열 복제 | 감소 |
| --- | ---: | ---: | ---: |
| 평면 디렉터리 2,048개, 결과 없는 검색 | 8,193 | 6,145 | 약 25% |
| 20,000행 텍스트의 19,960번째 행부터 20행 미리보기 | 20,001 | 532 | 약 97% |

수정 전은 제품 코드를 수정하기 전에 동일 fixture와 계측 wrapper로 실행했다. 검색은 2–3ms, 미리보기는 1ms 수준으로 시간 해상도와 실행 편차가 커서 속도 향상을 단정하지 않는다. 계측 대상은 `text_copy` 호출이며 전체 malloc 횟수나 최대 RSS가 아니다.

## 비동기 처리 판단

미디어 변환은 이미 별도 프로세스와 `waitpid(WNOHANG)`으로 실행하고, 외부 뷰어도 시작/폴링 API를 사용한다. 메인 루프는 진행 중 작업이 있을 때만 입력 대기 시간을 제한한다. Vim은 터미널을 넘기고 종료까지 기다리는 기존 정책을 유지한다.

검색·복사·삭제·휴지통은 동기 처리하면서 콜백에서 입력을 확인하고 진행 표시를 제한한다. 이는 협력적 취소이며 느린 파일시스템 syscall 자체를 중단시키는 비동기 작업은 아니다. 디렉터리 목록 로드와 텍스트 읽기도 동기다.

이번 로컬 fixture에서는 새 worker를 도입할 정도의 UI 정지를 입증하지 못했으므로 추가 비동기화는 도입하지 않았다. 느린 mount에서의 응답성을 보장하는 결론은 아니다. 다음 측정 우선순위는 대규모/느린 디렉터리 로드와 검색의 입력 지연, 먼 위치 텍스트 읽기다. 정지가 재현되면 읽기 전용 탐색부터 취소 가능한 작업으로 분리하고, ncurses는 UI 경로에서만 호출하며 오래된 결과가 현재 패널에 반영되지 않도록 해야 한다. 파일 변경 작업의 백그라운드화는 충돌 확인·부분 완료·종료 수명까지 함께 설계해야 한다. 스레드를 도입한다면 휴지통의 프로세스 전역 umask 변경과 신호/자식 프로세스 관리도 먼저 재검토해야 한다.
