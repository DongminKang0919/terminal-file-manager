# GitHub Releases 배포 계획

첫 공개 테스트 배포를 위한 검토 문서다. 첫 태그는 `v0.1.0-beta.1`을 후보로 두고, 실제 배포 전에 버전과 지원 환경을 확정한다.

## 첫 프리릴리스

- [ ] 아래 라이선스 결정을 마치고 README와 배포 파일에 해당 고지를 반영한다.
- [ ] 배포할 커밋을 정하고 [버전 헤더](../src/version.h)의 값과 태그를 맞춘다. 태그가 `v0.1.0-beta.1`이면 `tfile --version`은 `0.1.0-beta.1`을 표시한다.
- [ ] 해당 커밋의 깨끗한 소스에서 빌드하고 `make -j2 check`를 실행한다. 빌드 배포판·버전과 CPU 아키텍처를 기록한다.
- [ ] 검증할 Ubuntu와 WSL Ubuntu 환경을 정한다. 개발 패키지가 없는 환경에서 배포 바이너리의 로딩, `--version`, 대화형 실행과 기본 파일 작업을 확인한다. 필요한 런타임 라이브러리와 선택적인 미디어 도구를 구분해 안내한다. [설치 안내](INSTALL.md)
- [ ] 지원 대상별 `tar.gz`에 실행 파일과 설치·실행 안내, 확정된 라이선스 고지를 넣고 `SHA256SUMS`를 생성한다. 파일명에 버전·배포판·아키텍처를 넣는다. 예시는 `tfile-v0.1.0-beta.1-ubuntu-<version>-amd64.tar.gz`다.
- [ ] 검증된 커밋을 가리키는 태그로 GitHub 릴리스 초안을 만들고 **Pre-release**로 표시한다. 지원 환경, 변경점, 알려진 제한, 설치·업데이트 방법을 릴리스 노트에 적고 압축 파일과 체크섬을 첨부한다. [GitHub 릴리스 관리](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)
- [ ] 파일명, 체크섬, 버전, 태그의 대상 커밋을 확인한 뒤 게시한다. 게시 후 실제 첨부 파일을 내려받아 체크섬과 실행을 다시 확인한다. 첫 체험자에게는 해당 프리릴리스 링크를, 이후 버전 목록을 공유할 때는 Releases 페이지를 보낸다.

## 이후 버전과 사용자 업데이트

- [ ] 변경 후 새 버전과 새 태그로 위 절차를 반복한다. 예를 들어 베타 수정판은 `v0.1.0-beta.2`로 배포하고 릴리스 노트에 이전 버전 대비 변경점과 설정 호환성을 적는다.
- [ ] 사용자는 자신의 환경에 맞는 압축 파일을 받고 체크섬을 확인한다. tfile을 종료한 뒤 압축을 푼 디렉터리에서 `install -D -m 755 ./tfile "$HOME/.local/bin/tfile"`로 사용자 경로의 바이너리를 교체하고 `"$HOME/.local/bin/tfile" --version`으로 확인한다. 기존에 다른 경로에 설치했다면 해당 경로를 사용한다. 첫 배포의 업데이트 방식은 이 수동 교체로 잡는다.
- [ ] 배포가 반복되면 버전 태그를 기준으로 빌드·검증·패키징·초안 첨부를 수행하는 GitHub Actions 자동화를 검토한다.

## 라이선스 결정

현재 README에는 명시된 배포·재사용 라이선스가 없다고 적혀 있다. 다른 사람이 사용·수정·재배포할 수 있게 하려는 방향이라면 **MIT를 첫 후보**로 검토한다. MIT는 상업적 이용도 허용하며 배포 시 저작권 및 허가 고지를 포함하도록 한다. 본인이 상업적으로 운영할 계획이 있는지와, 다른 사람의 상업적 이용까지 허용할지는 각각 정할 수 있다. [MIT 원문](https://opensource.org/license/mit)

파생 제품을 홍보할 때 프로젝트 저작권자나 기여자 이름을 쓰는 데 별도 허락을 요구하고 싶다면 **BSD 3-Clause**도 후보가 된다. 이 라이선스도 상업적 이용을 허용한다. [BSD 3-Clause 원문](https://opensource.org/license/bsd-3-clause)

- [ ] 제3자의 상업적 이용과 수정본 재배포를 허용할지 확정한다.
- [ ] 수업 팀 프로젝트에서 가져온 코드나 자료가 현재 저장소에 있는지 확인한다. 있다면 해당 자료의 배포 권한과 표기 조건을 확인한다.
- [ ] 선택한 라이선스와 저작권 표기를 확정한 뒤 저장소 루트의 `LICENSE`, README, 배포 압축 파일에 반영한다.
