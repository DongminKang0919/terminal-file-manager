시작 기준은 목적지 폼 개선 커밋 `66f14ca`이며 작업 트리는 깨끗했다. 사용자 데이터를 테스트에 사용하지 않고 /tmp의 임시 디렉터리·격리 바이너리만 사용했다. 상태 분리는 `c5fd109`에 먼저 커밋했다. 두 번째 패널을 연결하기 전 기존 단일 화면의 `make check` 전체와 preview_test 재검사를 통과했다.

첫 이중 진입은 임시 후보를 완전히 초기화한 뒤 소유권을 넘긴다. 실패한 후보는 해제하며 기존 패널·미리보기를 유지한다. 명시적 단일 전환은 숨기는 패널의 표시만 해제한다. 재표시는 원본 이름을 복사한 뒤 한 번 갱신한다. 실패하면 이전 목록을 보존하고 STALE로 변경 작업을 차단한다. 리사이즈의 임시 숨김은 모드/표시를 해제하거나 목록을 조회하지 않는다. 종료는 두 패널·미리보기·최근 결과를 해제한다.

실제 파일 API 종료 후 원본은 기존 갱신 정책을 따른다. 이중 모드의 상대는 한 번 갱신하며, 좁은 화면에서도 두 패널이 참여한다. 일괄 실행은 대상 수에 관계없이 패널당 한 번이다. 명시적으로 숨긴 단일 모드의 상대는 재표시 때만 읽는다. 입력/확인 취소·목적지 검증·Browse는 이 갱신 경계를 호출하지 않는다. 각 실패 Result와 이전 목록은 독립적으로 유지한다.

## 실행 결과와 미확인 범위

최종 `make check` 전체, 추가 계측 검사와 Python 구문 검사, `git diff --check`가 통과했다. ASan/UBSan 17개 격리 검사도 `detect_leaks=0`, `halt_on_error=1`로 모두 통과했다. 최종 오류 안내 보완 후 17개 전체를 다시 실행하여 최초/재표시 할당 실패와 결과 표시 검사도 포함했다.

LSan을 켠 17개 실행은 ptrace 환경 제한의 fatal error로 종료되어 **누수 검사는 완료하지 못했다**. 명시적 소유권·FD·창 계측 성공이나 ASan/UBSan 성공을 전체 누수 없음으로 확대 해석하지 않는다. 모든 PTY를 sanitizer 실행 파일로 돌리지는 않았다. 실제 교차 파일시스템 이동과 모든 외부 동시 교체 경쟁은 새로 실행하지 않았으며 기존 EXDEV 주입·플랫폼 안전성 검사를 유지했다.

남은 제한은 고정된 80열 나란히 표시 기준, 작은 화면/긴 경로/큰 개수의 화면 생략, 명시적인 새로고침과 작업 종료/재표시 시점 갱신이다. STALE은 알려진 갱신 실패의 보호 상태이며 파일시스템 스냅샷이나 외부 변경 감시를 제공하지 않는다. 느린 동기 호출·개별 이동 중 취소 제한, 4,095바이트 전송 입력 상한, 진단 필드 한도, 덮어쓰기 금지·링크 비추적·자기 내부 전송 금지·잔여물 보존은 유지한다. 드래그 크기 조절·탭·설정 저장·비동기 실행·반대편 목적지 자동 지정은 이번 범위에 없다.
