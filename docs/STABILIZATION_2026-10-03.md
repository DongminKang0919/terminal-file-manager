## 실행으로 확인한 결함과 수정

1. 50×9 복사 폼의 충돌 오류는 원인이 앞에 있는 짧은 안내를 긴 작업 요약으로 덮어썼다. 폼에는 원인을 유지하고 요약·완료 수·바이트·갱신 결과는 기존 최근 결과에 보존한다. 취소는 실제 Result와 partial로 짧게 구분한다. 기존 PTY 전체가 이제 통과한다.
2. 시작은 app_init에서 목록을 읽은 뒤 다시 load_dir로 읽었다. 읽을 때 기본 정렬 후 메인 정렬도 했다. 계측으로 중복 조회/정렬을 확인했다. 시작의 재조회 제거, 메인 목록 읽기와 정렬을 분리했다. 기존 core_list의 picker 정렬은 그대로다. 경로 검증용 조회도 유지한다.
3. 재귀 검색은 매 진행 콜백마다 전체 검색 창을 그렸다. 4,200개 방문에서 화면 갱신 85회였다. 진행 렌더링에 100ms 제한을 두고 모든 콜백의 취소 입력 확인은 유지했다. 최종 결과는 즉시 그린다. 고정 시계 검사에서 성공·취소 각각 진행 출력 1회, 성공 입력 확인 최소 17회/취소 2회를 확인한다.

정적 소유권 검토에서는 목록 교체 후 오래된 포인터, 부분 할당 해제 누락을 실제 결함으로 확정하지 못했다. 추정만으로 구조를 개편하지 않았다. 할당 실패 주입 검사로 listing/refresh/search/preview 각각 첫 100번째까지 명시적 할당 실패를 시도하고 해제·FD·실패한 refresh의 기존 목록 보존을 확인했다. 실패 위치가 실제 할당 수를 넘으면 정상 실행도 포함된다.

## 통합·메모리·검증

- 변경 전: 반복 100회 RSS 5384–5384 KiB, 관측 FD 6–7, 최종 해제 후 6 FD.
- 변경 후: 반복 100회 RSS 4804–4804 KiB, 관측 FD 6–7, 최종 해제 후 6 FD.

반복은 탐색/Back/Forward/정렬, 미리보기 변경, 팝업, 취소 알림 상세, 4,000개 검색 결과 해제, 64KiB 이후 재귀 복사 취소를 포함한다. FD 관측에는 /proc/self/fd를 읽는 임시 FD 한 개가 포함된다. live preview reader가 있을 때 FD가 하나 늘고 닫은 뒤 돌아온다. RSS가 즉시 낮아지지 않는 것을 누수로 판정하지 않았다. 관측 범위에서 반복 증가가 없었으나 전체 프로그램의 누수 없음 증명은 아니다. explicit allocation tracker는 앱에서 직접 호출한 할당만 추적하며 libc/ncurses 내부 할당은 범위 밖이다.

- git diff --check 통과. architecture 검사와 기존 make check 검증 내용을 약화하지 않았다.

## 남은 제한과 다음 단계

실제 터미널 전송 지연, 보장된 콜드 캐시, 매우 긴 개별 줄의 최악 성능, 외부 프로세스와의 모든 파일 교체 경쟁을 측정으로 보장하지 않는다. sanitizer는 위 열거 범위이며 모든 PTY/플랫폼 테스트를 sanitizer 빌드로 실행한 것은 아니다. 단일 이동 호출 중 취소 불가, 원래 Result detail 256/path 1024 제한, 자동 롤백/잔여물 정리 없음은 그대로다. 스레드·비동기 엔진·무제한 캐시·이중 패널·새 기능은 추가하지 않았다. 향후 다중 선택/일괄 작업은 실제 구현 뒤 대상 소유권·한 번 갱신·성공/미실행 상태를 별도 검사해야 한다. LSan을 실행 가능한 비-ptrace 환경에서 다시 확인하는 것이 필요하다.
