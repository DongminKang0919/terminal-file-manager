# 방문 기록 키보드 동작 조사

## 결론과 변경 범위

기준 커밋 `bfa29e3`을 별도 `/tmp` 소스 복사본에서 빌드해 새 방문 기록 PTY 회귀 검사와 비교했다. 수정 전·후 모두 `[`/`]`, `Alt+←`/`Alt+→`와 마우스 혼합 흐름이 통과했다. 지원 단축키가 앞으로 기록을 지우거나 일반 방향키로 파싱되는 버그는 재현하지 못했다. 사용자가 누른 키와 터미널 설정이 없으므로 원래 관찰의 원인은 확정할 수 없다.

- `src/ui/main.c`: `[`/`]`와 Location 클릭을 `UI_BACK`/`UI_FORWARD`로 변환한 뒤 같은 `history_dir()`를 호출한다. Alt CSI도 `src/ui/input.c`의 `define_key()`로 같은 명령이 된다.
- `src/ui/controller.c`: 현재 선택·스크롤을 저장하고 `app_history()`를 호출한다. `src/core/files.c`는 `record=false`로 목록을 읽으며 성공한 경우에만 기록 인덱스를 옮긴다. 키보드와 마우스의 중복된 기록 처리 로직은 없다.
- 일반 `←`/Backspace는 `parent_dir()`를 통해 새 탐색을 기록한다. 일반 `→`/Enter는 선택 디렉터리를 연다. 이 키를 Back/Forward로 해석하면 관찰과 같은 차이가 생길 수 있다. 실제 Back 뒤 새 디렉터리를 방문하는 경우 앞으로 기록을 지우는 정책은 그대로 유지했다.
- 버튼의 비활성 색과 `A_DIM`은 해당 패널의 기록 인덱스·길이로 매번 그린다. 성공·실패·기록 분기 후 표시와 상태가 일치했다.

제품 변경은 안내와 Location 버튼에 한정했다. 경로행 폭이 80열 이상이면 `[< Back]` / `[Forward >]`를 표시하고 그보다 좁으면 기존 `[<]` / `[>]`를 유지한다. 표시와 클릭 범위는 `ui_history_layout()`을 공유한다. 도움말·README·사용자 가이드·레퍼런스에는 단축키와 일반 방향키의 차이, 기록 분기, 터미널 가로채기 시 대체 키를 명시했다. 최소 화면에서도 늘어난 도움말을 전부 표시하도록 도움말 행 용량을 늘렸다. 방문 기록·일반 방향키·입력 파서의 동작은 변경하지 않았다.

## PTY 입력과 제약

raw PTY에서 Alt CSI의 전달 바이트는 Back `1b 5b 31 3b 33 44`, Forward `1b 5b 31 3b 33 43`였다. 일반 좌우 CSI는 `1b 5b 44` / `1b 5b 43`로 구분된다. 이 바이트 전달 검사를 회귀 테스트에 포함했다. 프로그램은 Alt CSI를 ncurses 경로와 자체 파서 경로 모두에서 올바르게 처리했다.

PTY는 터미널 에뮬레이터나 물리 키를 생성하지 않는다. 사용 중인 터미널·데스크톱이 Alt 조합을 가로채거나 다른 escape 형식을 전달하는지는 이 환경에서 확인할 수 없다. 지원되는 CSI가 프로그램에 도착하지 않는 경우 `[`/`]`를 사용할 수 있다. 접근 거부는 일관된 재현을 위해 native 테스트에서 주입했고, 경로 삭제·재시도는 실제 파일시스템과 PTY에서 검사했다. 전체 프로젝트 테스트는 실행하지 않았으며 관련 검사만 실행했다.
