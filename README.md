# tfile

C와 ncursesw로 만든 터미널 파일 관리자입니다. 파일 목록과 미리보기를 함께 보면서 마우스 또는 키보드로 탐색·검색·파일 작업을 할 수 있습니다.

## 시작하기

Linux/WSL 환경, C11 컴파일러, `make`, ncursesw 개발 라이브러리가 필요합니다. UTF-8 로캘과 마우스 입력을 지원하는 터미널을 사용하세요.

```sh
make
./tfile
# 시작할 디렉터리 지정
./tfile /path/to/directory
```

최소 화면 크기는 **50열 × 9행**, 권장 크기는 **100열 × 24행**입니다. 모든 메뉴는 상단에 F키 번호순으로 배치됩니다. 작은 화면에서는 키 번호만 표시하며, **F9 Menu**를 누르면 명령 이름을 모두 확인할 수 있습니다.

## 처음 사용한다면

1. 목록에서 파일을 클릭하면 오른쪽에 정보와 텍스트 미리보기가 표시됩니다.
2. 디렉터리를 선택하고 왼쪽 목록 위 **Open**을 클릭하거나 더블클릭해 들어갑니다. 목록 위 **Parent**로 상위 디렉터리로 돌아옵니다. 상단 **[<] / [>]**는 이전·다음 방문 위치로 이동합니다. 파일은 선택하거나 **Open**을 누르면 오른쪽에서 미리 봅니다.
3. **F2 New**에서 **File / Directory** 타입을 선택하고 이름을 입력한 뒤 **Create**를 누릅니다. 이름이 겹치면 창 안에 경고가 표시되고, 입력한 이름을 바로 수정할 수 있습니다.
4. **F9 Menu → Options**에서 숨김 파일 표시, 미리보기 패널, 휠 이동량을 바꿀 수 있습니다.
5. 각 팝업 오른쪽 위 **[ x ]** 또는 `Esc`로 닫습니다.

여기서 창은 현재 터미널 안에 열리는 팝업입니다. 파일·디렉터리 생성, 복사·이동, 삭제 확인, 검색, 도움말, 메뉴, 옵션에 사용합니다. 팝업이 열린 동안 배경 목록은 마우스 입력을 받지 않습니다.

## 키보드와 마우스

| 키 | 동작 |
| --- | --- |
| `F9`, `m` | 전체 메뉴 |
| `F7` | 옵션 |
| `F1`, `?` | 도움말 |
| `↑`/`↓`, `k`/`j` | 선택 이동 |
| `PgUp`/`PgDn`, `Home`/`End` | 페이지 또는 처음·끝으로 이동 |
| `Enter`, `→` | 선택한 디렉터리 열기 |
| `Backspace`, `←` | 상위 디렉터리 (Parent) |
| `Alt+←` / `Alt+→`, `[` / `]` | 이전 / 다음 방문 위치 |
| `F2` | New: 파일/디렉터리 타입과 이름을 지정해 생성 |
| `F3`, `/` | 이름 검색 |
| `F4` | 같은 New 창을 디렉터리 타입으로 열기 (보조 단축키) |
| `F5` | 복사 |
| `F6` | 이동·이름 변경 |
| `F8`, `Delete` | 삭제 확인 |
| `r` | 새로고침 |
| `q`, `F10` | 종료 |

- 한 번 클릭하면 즉시 선택하고, 같은 항목을 빠르게 두 번 클릭하면 디렉터리를 엽니다.
- 왼쪽 목록 위에서 휠을 한 번 굴리면 기본적으로 선택 항목이 한 행씩 위아래로 이동하고 긴 목록도 스크롤됩니다. 짧은 목록에서도 선택이 이동합니다. 옵션에서 한 번에 1·3·5행을 선택할 수 있습니다.
- 오른쪽 **Preview** 위에서 휠을 굴리면 파일 정보와 본문을 위아래로 읽을 수 있습니다. 왼쪽 선택은 유지되며, 다른 파일을 선택하면 미리보기 위치가 맨 위로 초기화됩니다. 미리보기 하단에는 현재 행과 마지막 부분(`End`) 표시가 나옵니다. 도움말·검색 결과에서도 휠을 사용할 수 있습니다.
- 메뉴 항목과 팝업의 **Create / OK / Cancel / Delete / Search / Open** 버튼은 클릭으로 실행합니다.
- 입력 창에서 한글을 입력할 수 있고 `←`/`→`, `Home`/`End`, `Backspace`/`Delete`로 편집합니다. 입력 위치를 클릭해 커서를 옮기거나 `Tab`/`Shift+Tab`으로 초점을 옮길 수도 있습니다. `ć`, `ŗ`, `š`, `ƚ`처럼 내부 특수키 값과 같은 코드포인트의 일반 유니코드 문자도 원문 그대로 입력됩니다.
- 터미널 크기를 바꾸면 열린 팝업은 취소됩니다. 입력 중인 내용은 저장되지 않습니다.
- 옵션은 현재 실행에만 적용됩니다. 재실행하면 숨김 파일 표시·미리보기 켜짐, 휠 1행으로 돌아옵니다.

현재 절대 경로는 메뉴 바로 아래 **Location** 표시줄에 대비가 큰 배경색과 굵은 글씨로 표시합니다. 경로가 길면 앞부분을 `...`로 줄여 현재 디렉터리 쪽 끝부분을 우선 보여줍니다.

New 창의 타입은 마우스로 선택하거나 `Shift+Tab`으로 타입에 초점을 옮긴 뒤 `←`/`→` 또는 `Space`로 바꿉니다. `Enter`로 이름 입력에 돌아옵니다. 중복 이름이나 잘못된 이름 때문에 창이 닫히지 않으며 기존 파일을 덮어쓰지 않습니다.

메인 목록은 `Directory`(디렉터리), `File`(파일), `Link`(링크), `Other`(기타)를 글자로 표시합니다. 디렉터리는 하늘색, 실행 파일은 녹색, 링크는 노란색, 숨김 항목은 보라색으로 구분하며 선택한 행은 선명한 파란 배경으로 강조합니다. 검색 결과에서는 한 글자 종류 표시를 사용합니다. 바이너리 파일은 텍스트 미리보기를 생략합니다.

### 마우스 뒤로·앞으로 버튼

보조 버튼은 터미널이 SGR 마우스 확장 버튼 8/9를 전달할 때 이전·다음 방문 위치로 이동합니다. 터미널 자체가 버튼을 사용하거나 전달하지 않으면 상단 **[<] / [>]**, `Alt+←`/`Alt+→`, `[`/`]`를 사용하세요. 버튼을 누를 때 한 번만 이동하며, 팝업에서는 배경 탐색을 실행하지 않습니다.

방문 기록은 실행 중 최대 128개를 유지합니다. 뒤로 이동한 뒤 새로운 디렉터리를 열면 기존 앞으로 기록은 지워집니다. 새로고침·파일 생성은 방문 기록을 추가하지 않으며, 삭제되거나 접근할 수 없는 기록으로 이동하면 현재 위치를 유지하고 오류를 표시합니다. **Parent**는 방문 기록과 무관하게 상위 디렉터리로 이동합니다.

프로토콜 참고: [xterm 마우스 입력](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html#h2-Mouse-Tracking), [ncurses 마우스 API](https://invisible-island.net/ncurses/man/curs_mouse.3x.html).

## 검색

**F3**에서 검색어를 입력하고 **Search**를 누르면 현재 디렉터리 아래에서 이름에 검색어가 포함된 항목을 찾습니다. 영문 대소문자를 구분하지 않으며 파일 내용은 검색하지 않습니다. 숨김 항목도 검색 대상입니다.

결과는 상대 경로로 구분합니다. 클릭해 선택한 뒤 **Open**, 더블클릭 또는 `Enter`로 해당 위치로 이동하세요. **Search**나 `/`로 다시 검색할 수 있습니다. 검색 중 **Cancel** 또는 `Esc`를 누르면 중단 시점까지의 결과를 남겨 열어볼 수 있습니다. **[ x ]**는 검색을 중단하고 창을 닫습니다.

검색어 입력과 결과는 같은 창을 사용하며, 어느 단계에서도 오른쪽 위 **[ x ]**로 닫을 수 있습니다.

- 결과 화면은 **Complete**(완료), **Incomplete**(일부 누락), **Cancelled**(사용자 중단), **Error**(오류 중단)를 구분합니다. 검색 한도에 도달하면 기존처럼 **(limit)**를 함께 표시합니다.
- 접근 불가·검색 도중 사라진 항목 등은 건너뛴 디렉터리/항목 수와 첫 누락의 경로·원인을 표시합니다. 접근하지 못한 디렉터리 내부의 실제 누락 파일 수까지 계산할 수는 없습니다. 누락 정보는 메모리 사용을 제한하기 위해 모든 경로 대신 건수와 첫 원인만 보관합니다.
- 메모리 부족이나 디렉터리 읽기 오류 등은 정상 완료로 표시하지 않습니다. 이미 수집한 결과는 가능한 한 유지하므로 오류·취소 뒤에도 결과를 열거나 다시 검색할 수 있습니다.
- 숨김 표시가 꺼져 있어도 숨김 파일을 검색할 수 있습니다. 숨김 결과를 **Open**하면 필요할 때 숨김 표시를 켜고 **hidden files shown**을 알린 뒤 정확한 항목을 선택·미리보기합니다. 표시 설정은 이후에도 유지됩니다. 결과가 사라졌거나 이동·선택에 실패하면 성공 메시지를 표시하지 않으며 기존 위치·목록·방문 기록·숨김 설정을 유지합니다.

최대 100,000개 항목, 10,000개 결과, 깊이 64단계까지 탐색합니다.

## 복사·이동: 경로를 몰라도 선택해서 실행

**Copy(F5)** 또는 **Move(F6)**를 열고 다음 항목을 확인하세요. 메인 목록에서 선택한 항목이 원본으로 미리 지정됩니다.

1. **Choose source**: 다른 파일이나 디렉터리를 고르려면 클릭합니다. 원본 선택 창에서 항목을 선택하고 **Use selected**를 누릅니다.
2. **Browse destination**: 디렉터리를 더블클릭하거나 **Open**으로 들어가고, 원하는 위치에서 **Use directory**를 누릅니다. **Parent**로 상위 디렉터리로 이동할 수 있습니다.
3. **Keep original name / Change name**: 원래 이름을 유지하거나 새 이름을 지정합니다. 이름을 바꾼 뒤에도 원래 이름으로 되돌릴 수 있습니다.
4. 설정을 확인하고 **Copy now / Move now**를 눌러 실행합니다. 복사는 원본을 유지하고, 이동은 원본 위치를 바꿉니다. 같은 디렉터리에서 이름만 바꾸면 이름 변경입니다.

이름 중복이나 접근 오류는 같은 창에서 안내하고 설정을 유지합니다. **Cancel / [ x ] / Esc**로 작업을 취소할 수 있습니다. 디렉터리 선택 창에서 취소하면 복사·이동 설정으로 돌아옵니다.

키보드로는 `Tab`/방향키로 필드를 고르고 `Enter`로 엽니다. 선택 창에서 방향키로 탐색, `Enter`로 디렉터리 열기, `Space`로 선택을 확정합니다. 경로를 알고 있다면 **Enter path** 또는 `p`로 직접 입력할 수도 있습니다. 작은 화면에서는 필드 목록을 스크롤합니다.

## 파일 작업의 범위

- 생성 창은 현재 디렉터리에 빈 파일 또는 디렉터리를 만듭니다. 파일 내용 편집기는 포함하지 않습니다.
- 복사·이동은 원본과 대상 디렉터리를 선택하는 방식입니다. 대상 이름에는 경로 구분자 `/`를 넣지 않습니다.
- 기존 대상을 덮어쓰지 않으며, 디렉터리를 자기 내부로 복사·이동하는 것을 차단합니다.
- 이동은 같은 파일 시스템 안에서 지원합니다.
- 상단 **F8 Delete**, 키보드 `F8` 또는 `Delete`, 전체 메뉴 어디서 실행하든 대상 이름과 삭제 여부를 먼저 묻습니다. 기본 선택은 **Cancel**이며, **Delete**를 명시적으로 선택해야 삭제합니다. 디렉터리 삭제는 내부까지 재귀적으로 삭제하며 휴지통이나 실행 취소 기능은 없습니다.
- 새로고침이 실패하면 **Refresh failed**와 원인을 표시하고 기존 위치·목록·선택을 유지합니다. 실패를 **Refreshed**로 표시하지 않습니다.
- 생성·복사·이동·삭제 자체는 성공했지만 목록 갱신만 실패하면 **File created / Copied / Moved / Deleted …; list refresh failed: …**로 두 결과를 구분합니다. 작업을 다시 실행하기 전에 접근 권한 등을 확인하고 `r`로 목록을 갱신하세요.
- 대용량 복사·이동·삭제는 동기 방식으로 실행됩니다.

### 재귀 파일 작업의 안전성 및 실패 정책 (POSIX)

- 일반 탐색은 디렉터리 심볼릭 링크를 열 수 있습니다. **재귀 복사는 링크의 문자열 대상만 복제하고, 삭제는 링크 자체만 제거**하며 링크 대상으로 내려가지 않습니다. 파일 작업의 경로 조상도 FD로 한 단계씩 열며 심볼릭 링크인 조상은 거부합니다. UI의 일반 탐색은 기존처럼 실제 경로를 해석합니다.
- 작업 중에는 `openat`/`fstatat`/`readlinkat`/`unlinkat` 등으로 열린 부모 디렉터리에 상대적으로 접근합니다. 디렉터리·일반 파일을 열 때 `O_NOFOLLOW`와 장치/inode 일치 검사를 사용하고, 디렉터리 작업 완료 시 이름이 같은 대상을 가리키는지도 확인합니다. 경로 교체가 감지되면 성공으로 처리하지 않습니다. 목적지는 기존 파일·디렉터리·링크를 덮어쓰거나 병합하지 않습니다. 자기 내부 복사·이동 금지도 유지합니다.
- 복사 디렉터리는 임시 **0700**으로 만들고 자식 처리가 끝난 뒤 최종 권한을 적용합니다. 일반 파일은 **0600에서 umask를 적용한 권한**으로 생성합니다. 성공 시 파일·디렉터리의 최종 권한은 **`원본 모드 & 0777 & ~작업 시작 시 umask`**입니다. setuid/setgid/sticky, 소유자, ACL, 타임스탬프는 복제하지 않습니다. 링크 권한은 POSIX 링크 생성 규칙을 따릅니다. umask가 0777처럼 엄격해도 복사를 완료한 뒤 해당 최종 권한을 적용합니다.
- 현재 단일 스레드 POSIX 백엔드는 umask를 읽을 때와 임시 디렉터리를 만들 때만 프로세스 umask를 잠시 변경하고 즉시 복원합니다. 향후 파일 작업을 여러 스레드에서 실행한다면 이 부분의 동기화/구현 변경이 필요합니다.
- 실패 시 **자동 롤백이나 잔여 대상 삭제를 하지 않습니다.** 완료된 파일, 쓰다 만 파일, 생성한 디렉터리가 남을 수 있습니다. 미완료 디렉터리는 임시 0700 권한으로 남고, 완료된 하위 항목은 최종 권한을 가질 수 있습니다. 작업 중 다른 사용자가 바꾼 이름을 정리한다며 삭제하지 않습니다. 잔여 대상을 확인한 뒤 사용자가 직접 정리해야 하며, 동일 이름으로 재시도하면 기존 대상 오류를 반환합니다. 삭제 역시 이미 삭제된 항목은 복원하지 않습니다.
- 오류 결과는 실패 경로와 **`partial`** 여부를 포함합니다. 화면에는 **Partial operation**(이 작업이 일부 변경을 수행함) 또는 **No changes**(이 작업의 변경 없음), 원인, 실패 경로를 표시합니다. 매우 긴 경로는 앞부분을 `...`로 줄이고 실패 지점인 뒷부분을 유지합니다. 내부 경로 진단은 최대 1023바이트, 화면용 오류는 최대 255바이트이며, 실제 작업 경로는 동적 문자열과 FD를 사용합니다.
- 재귀 처리는 **64단계**로 제한합니다(선택 대상 깊이 0, 깊이 64에서 중단). 열린 디렉터리는 삭제 시 깊이당 1개, 복사 시 깊이당 2개와 조상 확인용 소수의 임시 FD가 필요합니다. 프로세스 FD 한도가 더 낮으면 그 지점에서 오류를 반환하고 모든 작업 FD와 버퍼를 해제합니다. 64KiB 파일 버퍼는 힙에서 한 번 할당하여 재사용합니다.
- 이 방어는 파일시스템 스냅샷이나 트랜잭션을 제공하지 않습니다. 열린 디렉터리가 다른 위치로 옮겨지면 해당 FD가 가리키는 원래 디렉터리에서 진행할 수 있고, 최종 이름 확인 후 삭제 사이의 이름 교체까지 원자적으로 차단하지는 못합니다. 같은 권한의 프로세스가 새 디렉터리 생성 직후 다른 실제 디렉터리로 교체하는 경쟁, 마운트 변경, 복사 중 원본 내용 변경에 대한 완전한 격리는 보장하지 않습니다. 최종 이름 삭제는 링크를 따라가지 않으며, 실패 정리를 위해 기존 사용자 파일을 지우지 않습니다.

## 개발과 검증

```sh
make             # Linux/WSL + ncursesw 프로그램
make check-core  # UI 없이 핵심 로직·POSIX 구현·의존성 검사
make check       # 위 검사 + 실제 터미널 입력(PTY) 통합 테스트
make clean
```

테스트에는 Python 3가 필요합니다. 모든 파일 작업은 임시 디렉터리에서 실행합니다.

- 핵심 로직: 서로 독립적인 앱 상태, 정렬·숨김 필터, 생성·복사·이동·삭제, 검색 취소·한도, 페이지 단위 미리보기와 EOF를 확인합니다.
- 플랫폼: 루트·상대·긴 경로, 파일 정보, 심볼릭 링크, 이름 충돌, 접근 오류, 덮어쓰기 없는 이동을 확인합니다. 권한 제한 검사는 root로 실행할 때 생략합니다.
- 파일 작업 안전성: 테스트 전용 동기화 지점에서 원본/목적지 디렉터리를 링크로 교체하고 외부 표식 보존을 검사합니다. 비 root로 0555 복사와 umask(0022/0077/0777), PATH_MAX 초과 경로, 깊이/FD 한도, 부분 쓰기 실패, 잔여 대상과 FD 정리를 검증합니다. root로 실행하면 해당 테스트 자식만 nobody로 권한을 낮춥니다.
- 2차 회귀: 비 root 접근 오류와 제어된 메타데이터/메모리/읽기 실패로 검색 상태와 결과 보존을 검사합니다. 숨김 결과의 정확한 선택 및 실패 시 상태 보존, 파일 작업 성공 후 목록 갱신 실패도 확인합니다. 주입은 테스트 실행 파일의 링크 래퍼에서만 수행합니다.
- UI: 실제 PTY에서 특수키 코드포인트와 겹치는 유니코드 입력, 한글 편집, 검색 완료·누락·취소·오류 표시, 숨김 결과 열기, 새로고침 오류를 검증합니다. 기존 팝업·마우스·파일 작업·미리보기·작은 화면 검사도 유지합니다. PTY 권한 검사는 root 실행 시 생략되며, 별도 네이티브 권한 검사는 nobody로 권한을 낮춰 실행합니다.
- 의존성: 핵심 로직에 ncurses/POSIX 자료형이 유입되거나 UI에서 파일시스템에 직접 접근하는 변경을 검사합니다.

## 코드 구조와 의존성

```text
src/
  model.h, model.c          공통 데이터·오류 코드·메모리 해제
  core/
    core.h                  UI와 독립적인 핵심 API
    files.c                 앱 상태·목록·정렬·탐색
    operations.c            생성·복사·이동·삭제 정책과 결과
    search.c                검색 엔진·진행/취소 콜백
    preview.c               페이지 단위 텍스트 데이터
  platform/
    platform.h              OS 독립적인 플랫폼 계약
    posix.c                 Linux/WSL 파일 접근·경로·시계 구현
  ui/
    ui.h                    터미널 상태와 UI 내부 인터페이스
    main.c, controller.c    입력 루프·작업 요청·결과 표시
    input.c                 터미널 입력·SGR 마우스 보조 버튼 해석
    ui.c, theme.c           화면·색상
    dialogs.c, transfer.c   팝업·복사/이동 설정·선택기
    search.c, preview.c     검색/미리보기 화면
    help.c                  도움말
```

의존 방향은 **UI → core → platform**입니다. 공통 `model`은 어느 레이어도 참조하지 않습니다. UI 헤더는 UI 내부에서만 사용하며, 핵심·플랫폼 헤더에는 ncurses, `struct stat`, `mode_t`, OS 핸들을 노출하지 않습니다. 파일 읽기·쓰기·조회는 모두 플랫폼 구현에 있습니다. 디렉터리 목록과 선택기는 동일한 핵심 조회 API를 사용합니다.

`AppState`는 현재 경로·목록·설정·방문 기록을 소유합니다. `UiContext`는 앱 상태와 별도로 선택·스크롤·미리보기 위치·상태 문구를 관리합니다. 가변 전역 상태 없이 필요한 상태를 인자로 전달합니다. 핵심 작업은 화면을 갱신하지 않고 `Result`를 반환하며, 확인 창·사용자 메시지·성공 후 목록 갱신은 UI가 담당합니다.

검색은 UI 콜백으로 진행 상태를 전달하고 취소 요청을 받습니다. 콜백으로 전달된 결과는 빌린 데이터이며 저장하거나 해제하지 않습니다. 미리보기는 요청한 페이지와 끝 도달 여부만 반환하여 전체 파일을 메모리에 적재하지 않습니다. 기존처럼 긴 한 줄은 최대 4,175바이트 단위로 읽습니다.

### 메모리 소유권

- 경로 API가 반환한 문자열은 호출자가 `free()`합니다. 핵심·플랫폼 경로에는 고정된 `PATH_MAX` 배열을 사용하지 않습니다.
- `FileInfo`·`FileList`·`SearchResult`·`PreviewText`는 각각 제공되는 해제 함수를 사용합니다. 목록의 항목은 목록과 함께 해제하므로 별도로 해제하지 않습니다.
- 출력 구조체는 새 변수 또는 해제된 변수로 전달합니다. 초기화된 `AppState`는 재초기화 대신 탐색/새로고침 API를 사용하고, 마지막에 `app_free()`합니다.
- 기존 터미널 입력 창만 최대 4,095바이트 입력 제한을 유지합니다. 그보다 긴 경로는 복사·이동 입력 창에서 잘라 사용하지 않고 오류를 표시합니다.

### Windows 포팅 경계

현재 제공하는 구현은 **Linux/WSL 전용**입니다. Windows 네이티브 빌드나 동작 검증은 포함하지 않습니다.

Makefile의 `PLATFORM` 변수는 플랫폼 소스를 빌드 시 선택합니다(현재 `posix`만 제공). 향후 Windows 구현은 `platform.h` 계약에 맞춰 파일 접근, 경로 결합·부모·이름 추출·해석·이름 검증·하위 경로 판정, 단조 증가 시계를 구현하면 됩니다. 드라이브·UNC·대소문자 규칙이나 UTF-16 변환을 핵심 코드로 가져오지 않습니다. 경로 문자열의 원래 바이트를 핵심에서 임의로 정규화하지 않으며, Windows의 인코딩 변환은 해당 플랫폼 구현에서 처리합니다.

POSIX 권한은 `FileInfo`의 선택적 메타데이터입니다. Linux의 `renameat2(RENAME_NOREPLACE)` 의존성도 플랫폼 구현 안에만 있으며, 지원하지 않는 환경에서는 덮어쓰기 가능한 이동으로 우회하지 않고 오류를 반환합니다. 터미널 라이브러리와 문자 폭 처리(`wcwidth` 등)는 UI 내부에 남으므로 Windows UI 포팅 시 별도로 검토해야 합니다.

플러그인 등록, 런타임 백엔드 선택, 범용 가상 파일시스템, Windows 경로 파서의 선행 구현은 도입하지 않습니다.
